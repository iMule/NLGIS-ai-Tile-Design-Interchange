# TDI workflow

## 1. Author or select a brief

Identify the map purpose, geography, audience, preferred scale, important layers, and visual character. A reviewed library brief can provide a stable starting point.

## 2. Research and normalize

An agent or human may gather references and normalize the result into the TDI structure. Research sources and rights should remain explicit rather than hidden in a prompt.

## 3. Select a provider contract

Combine the TDI brief with a pinned source/template contract. This is where provider layer names, glyphs, sprites, expressions, and native syntax enter the process.

## 4. Compile and validate

Produce the provider-native style plus a translation report and package manifest. Validate schema shape, required semantic layers, attribution, accessibility constraints, and provider compatibility.

Rendering and editor acceptance should be reported separately from structural validation.
